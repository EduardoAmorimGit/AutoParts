# AGENTS.md

Spring Boot 4.1.1 REST API (Java 17, Maven). Early-stage. Product catalog: Flyway migration + `products` table, JPA entity/repository, `ProductService` (CRUD + DTOs + validation) and REST API `/api/products` (`ProductController` + `@RestControllerAdvice`). Reads are public; writes require HTTP Basic (`ADMIN_USER`/`ADMIN_PASSWORD`, dev defaults `admin`/`admin`). `GET /api/products` is paginated/sorted (Spring Data `Pageable`, default size 20, max 100, default sort `id,asc`) and returns the `common/PageResponse` envelope (`content`, `page`, `size`, `totalElements`, `totalPages`, `first`, `last`). SKUs are normalized (trim + uppercase, `Locale.ROOT`) before persistence and duplicate checks.

- Freeze 8: vehicle plate lookup (`/api/vehicles/lookup`) via Simples API + product/vehicle compatibility (N:N). The external provider is isolated under `integration/vehicle` behind the `VehicleLookupProvider` interface; only `SimplesApiVehicleLookupProvider` knows the provider URL/headers/JSON. `RestClient` (Spring 7) is used, no new dependency. The API key comes from `simples-api.api-key=${SIMPLES_API_KEY:}`; when blank the provider bean is absent and `/api/vehicles/lookup` returns 503. `Vehicle` is keyed by a normalized (trim + uppercase, hyphen/space removed) unique `plate`; lookup reuses an existing plate without calling the provider again. Provider JSON is parsed as `tools.jackson.databind.JsonNode` (Jackson 3 has no `tools.jackson` `@JsonProperty`), and missing/null fields are kept null. Compatibility is the `product_vehicle` join table (UNIQUE + FKs with ON DELETE CASCADE).

## Commands
Use the Maven wrapper (Maven 3.10.0), not a system `mvn`.
- Start local DB: `docker compose up -d` (Postgres 17 on `localhost:5433`); stop: `docker compose down`
- Build: `.\mvnw.cmd clean package` (Windows) / `./mvnw clean package`
- Run: `.\mvnw.cmd spring-boot:run`
- All tests: `.\mvnw.cmd test`
- Single test: `.\mvnw.cmd test -Dtest=AutopartsMavenApplicationTests`
- Compile only: `.\mvnw.cmd compile`

## Gotchas
- Base package is `com.autoparts_maven.autoparts_maven` (underscores, not dots) and lives under `src/main/java/com/autoparts_maven/autoparts_maven/`. Match it exactly for new code.
- `application.properties` uses `DB_URL` (default `jdbc:postgresql://localhost:5433/autoparts`), `DB_USERNAME` and `DB_PASSWORD` (both default to `autoparts`, matching `docker-compose.yml`). Integration tests use the `test` profile (`src/test/resources/application-test.properties` + `@ActiveProfiles("test")`), which points to a dedicated `autoparts_test` schema in the same Postgres; Flyway creates it on first run. Run `docker compose up -d` before the tests.
- Host port **5432 is occupied by a native PostgreSQL 18 Windows service** (`postgresql-x64-18`). The Docker Postgres is intentionally published on **5433**; do not move it back to 5432.
- Schema is managed by Flyway through `spring-boot-starter-flyway`. Plain `flyway-core` will NOT run migrations in Spring Boot 4 (autoconfiguration is in the starter). Migrations live in `src/main/resources/db/migration` (naming `V<n>__desc.sql`). JPA runs with `ddl-auto=validate`, so entities must match the migrated schema.
- PostgreSQL is the only runtime datasource. Adding tests that boot the context needs a reachable Postgres or an override.
- Lombok is wired through `maven-compiler-plugin` `annotationProcessorPaths` (both compile and test-compile). Keep that config if editing plugin settings.
- This is Spring Boot 4: web uses `spring-boot-starter-webmvc` and test starters are per-module (`spring-boot-starter-*-test`), not the older `spring-boot-starter-web` / aggregate `spring-boot-starter-test`. In Boot 4 `@AutoConfigureMockMvc` lives in `org.springframework.boot.webmvc.test.autoconfigure`.
- `spring-boot-starter-security` is on the classpath with `config/SecurityConfig` (Spring Security 7 lambda DSL). `GET /api/products/**` and `/actuator/health` are public; writes (`POST/PUT/DELETE /api/products/**`) require HTTP Basic with the `ADMIN` role (`ADMIN_USER`/`ADMIN_PASSWORD`, dev defaults `admin`/`admin`). 401/403 return `ProblemDetail` JSON via `ProblemDetailAuthenticationEntryPoint`/`ProblemDetailAccessDeniedHandler`. `DispatcherType.ERROR` is permitted so error responses are not masked as 401. Controller tests authenticate with `spring-security-test` (`httpBasic(...)` / `@WithMockUser`).
- `product/ProductExceptionHandler` is a global `@RestControllerAdvice` (name is legacy) that maps domain errors (404/409/400-validation) **and** framework errors (bad path variable, malformed body, invalid sort, unsupported method/media type, unknown path) to `ProblemDetail` (`application/problem+json`). `GET /api/products` returns the `common/PageResponse` envelope. SKUs are normalized (trim + uppercase, `Locale.ROOT`) in `ProductService` before persistence and duplicate checks.
- Vehicle domain: `vehicle/VehicleService.lookupByPlate` normalizes/validates the plate, reuses an existing `Vehicle` or fetches from the provider and persists it (only when `VehicleLookupProvider` is configured; otherwise `VehicleLookupDisabledException` → 503). Provider failures map to `ProblemDetail`: 401/403 → 502, 429 → 429, 422 → 502, 503/unreachable → 503, unknown → 502, generic `RestClientException` (communication/conversion) → 502. The provider never exposes upstream messages, bodies or headers to clients, and logs only technical info (status code / exception class), never the plate, API key, headers or payloads. `Vehicle` persistence stores the plate (indirect personal data, LGPD) plus technical fields solely to link a vehicle to compatible products and avoid re-querying the provider; no owner/CPF/address or provider `city`/`state` are stored, and `color` was dropped from persistence (V4) and from `VehicleResponse` (no compatibility purpose). There is no automated retention/purge job yet. `GET /api/vehicles/**` and `POST /api/vehicles/lookup` are public; other `/api/vehicles/**` writes require `ROLE_ADMIN`. `GET /api/products/{id}/vehicles` and `GET /api/vehicles/{id}/products` return the `PageResponse` envelope. Tests use `VehicleLookupTestConfig` (`@Import`) to stub the provider; the real provider is never called in tests.

## Conventions
- `HELP.md` is gitignored and is stock Spring Initializr boilerplate; ignore it.
- `.gitattributes` pins `mvnw` to LF and `*.cmd` to CRLF; don't reformat those line endings.
- `.env*` files are gitignored. Never commit secrets; rely on env vars.
- Default branch is `main`.
